# 角色日记

角色日记让每个角色在每天设定的时间，根据当天与用户的对话写一篇第一人称日记。MoriBot 负责生成、保存和调度，后台与 MoriMobile 负责查看。

## 1. 开关与时间

全局设置位于「系统设置 → 角色日记」：

| 设置 | 说明 |
| --- | --- |
| 是否开启 | 默认关闭；关闭后仍可通过角色卡单独开启 |
| 全局时间 | 服务器本地时间，默认 `23:30` |

角色卡可以单独覆盖：

| 字段 | 说明 |
| --- | --- |
| `diary_enabled` | `null` 跟随全局；`true` 强制开启；`false` 强制关闭 |
| `diary_time` | `null` 跟随全局；`HH:MM` 使用角色自己的时间 |

解析规则：

```text
diary_enabled != null → 使用角色开关
diary_enabled == null → 使用全局开关

diary_time != null → 使用角色时间
diary_time == null → 使用全局时间
```

因此可以在全局关闭日记的情况下，只为少数角色开启；也可以让某个角色在更早或更晚的时间写日记。

## 2. 自动生成

`DiaryScheduler` 每 30 秒检查一次服务器本地时间：

1. 找到已启用、已到设定时间且今天还没有日记的角色。
2. 读取该角色当天的对话记录，最多 80 条、总字符数不超过 30000。
3. 将角色名称、简介、人物设定和对话记录组装成提示词。
4. 调用角色指定的对话模型；未指定时使用系统默认对话模型。
5. 保存一篇日记，同一角色同一天只保留一篇。
6. 生成失败会在 10 分钟后重试，避免频繁请求。

如果当天没有对话，仍会生成一篇安静的日常记录，但提示词会明确要求不要虚构用户发言。

服务重启后，如果当天已经超过设定时间且还没有日记，会补生成当天的日记。

## 3. 后台页面

左侧菜单「日记」提供：

- 按角色筛选
- 查看完整日记
- 手动生成指定角色、指定日期的日记
- 重新生成同一天的日记（覆盖原内容）
- 删除日记

手动生成同样使用当天/指定日期的对话作为上下文。

## 4. 数据

日记保存在 `character_diaries` 表：

| 字段 | 说明 |
| --- | --- |
| `character_id` | 角色 ID |
| `character_name` / `character_avatar` | 生成时的角色快照，角色删除后仍可显示 |
| `date` | 本地日期 `YYYY-MM-DD` |
| `content` | 日记正文 |
| `provider_id` / `model` | 生成使用的模型 |
| `source_message_count` | 参考的对话条数 |

日记随 SQLite 数据库一起进入备份和迁移，不需要单独处理媒体文件。

## 5. API

后台 JWT：

```http
GET  /api/v1/diaries?character_id=1&limit=50&offset=0
POST /api/v1/diaries/generate
DELETE /api/v1/diaries/{diary_id}
```

生成请求：

```json
{
  "character_id": 1,
  "date": "2026-11-16"
}
```

`date` 为空时使用服务器当天日期。

MoriMobile 设备令牌只读：

```http
GET /api/v1/mobile/app/diaries?character_id=1&limit=100&offset=0
```

## 6. 限制

- 每个角色每天只有一篇日记；重新生成会覆盖原内容。
- 日记生成依赖对话模型，模型不可用时会返回 409/502 并记录日志。
- 当前不支持手动编辑日记正文，只支持重新生成或删除。
- 日记时间使用服务器本地时区，不是手机时区。
